# Как работать с Библиотекой КАИТ

## 1. Что установить

| Программа | Версия проверки | Назначение |
|---|---|---|
| Git | 2.x | Клонирование, ветки, проверка diff |
| PHP | 8.5.12 на стенде; приложение требует PHP 8+ | Выполнение приложения и PHP_CodeSniffer |
| Python | 3.12; подходят Python 3.10+ | Создание проверочной SQLite-базы и штатная проверка модуля |
| VS Code | 1.146.0 | Основной редактор |
| Расширения VS Code | Intelephense 1.18.5, EditorConfig 0.18.2, PHP Debug 1.40.2 | Форматирование, правила сохранения, поддержка отладки |
| Apache NetBeans | 31 и полный JDK 21 | Вторая среда разработки |
| PHP_CodeSniffer / PHPCBF | 4.0.4 | Проверка и автоисправление PSR-12 |

PHP должен содержать PDO, pdo_sqlite, mbstring, session, json, filter, tokenizer, xmlwriter, SimpleXML и Phar. Для основного варианта с MySQL также нужен pdo_mysql. Полный JDK нужен для графического интерфейса NetBeans; одной headless-сборки Java недостаточно.

Линтеры уже включены в репозиторий преподавателя. Разместите его рядом с проектом:

```sh
git clone https://github.com/AlexandrAndreevichB/PP03.git PP03-teacher
git clone --branch practice/m04 https://github.com/12112007df/kait-library.git kait-check
cd kait-check
```

Ветка `practice/m04` остаётся доступной после слияния. Для обычной работы после сдачи можно клонировать `main`.

## 2. Как запустить проект

### Проверенный вариант для разработки с отдельной SQLite-базой

Команды выполняются из корня клона `kait-check`. SQLite используется для локальных проверок; основной MySQL-вариант описан в README.md. Каждой копии проекта нужна собственная база. Следующие команды рассчитаны на новую копию без `.env` и без существующей базы.

```sh
python practice/m01/init-sqlite.py ../kait-check-data/library.sqlite
python -c "from pathlib import Path; db=Path('../kait-check-data/library.sqlite').resolve(); Path('.env').write_text('APP_NAME=Библиотека КАИТ\nAPP_URL=http://127.0.0.1:8085\nAPP_DEBUG=false\nDB_DRIVER=sqlite\nDB_NAME='+db.as_posix()+'\n',encoding='utf-8')"
php -S 127.0.0.1:8085 -t public
```

В Linux вместо `python` может потребоваться `python3`. Скрипт создания базы откажется перезаписывать существующий файл: используйте новую папку данных. Не заменяйте уже настроенный `.env` без сохранения его содержимого.

На проверочном Linux-стенде вместо установленного PHP использован официальный переносимый FrankenPHP 1.13.5 с PHP 8.5.12. Его исполняемый файл находится вне репозитория. Для него последняя команда заменяется на:

```sh
../m04-tools/frankenphp php-server --root public --listen 127.0.0.1:8085
```

Для команд линтера ниже `php` в таком окружении заменяется на `../m04-tools/frankenphp php-cli`. В Windows можно использовать PHP из XAMPP: например, `C:\xampp\php\php.exe`. Установка PHP и путь к нему относятся к настройке компьютера, а не к содержимому репозитория.

Откройте http://127.0.0.1:8085/. Учебные записи из `database/seed.sql`:

| Роль | Логин | Пароль |
|---|---|---|
| Библиотекарь | librarian@kait20.ru | password |
| Студент | volkova@student.kait20.ru | password |
| Преподаватель | kuznetsov@kait20.ru | password |

Это демонстрационные данные для отдельного локального стенда. Для остановки сервера нажмите Ctrl+C. Для проверки после форматирования выполните вход библиотекарем, поиск книги и контрольные сценарии выдачи из `practice/m03/metrics.md`. Автоматизированная проверка выдачи использует `practice/m03/control-run.py`; исходную базу необходимо восстанавливать перед каждым сценарием, как делает этот скрипт.

## 3. Настройки редактора

В VS Code откройте корень клона, подтвердите доверие своему проекту и установите рекомендованные расширения через Extensions → поиск `@recommended`. `.vscode/extensions.json` содержит три расширения из таблицы выше. В `.vscode/settings.json` заданы UTF-8, LF, четыре пробела, отключено определение отступов по старому содержимому, выбран форматтер Intelephense и скобки PSR-12.

`.editorconfig` задаёт UTF-8, LF, четыре пробела, финальный перевод строки и удаление пробелов в конце строк. Markdown сохраняет конечные пробелы для переноса строк; `.cmd` и `.bat` сохраняются с CRLF в рабочей папке. `.gitattributes` хранит текст в Git с LF и задаёт отдельные правила для Windows-скриптов и двоичных файлов.

Очищенный профиль `practice/m04/vscode.code-profile` содержит только переносимые настройки и три рекомендуемых расширения; служебное состояние IDE в него не включено. Его можно импортировать через Profiles → Import Profile. Для работы с кодом достаточно проектных файлов и рекомендованных расширений; вход в аккаунт и Settings Sync не требуются.

В NetBeans откройте PHP-проект из `nbproject/`. В Properties → Formatting выберите проектные настройки: четыре пробела, Expand Tabs to Spaces. NetBeans не читает `.editorconfig`, поэтому соответствующие правила продублированы в `nbproject/project.properties`. Личные настройки `nbproject/private/` исключены из Git. Экспорт `practice/m04/netbeans-settings.zip` импортируется через Tools → Options → Import; выбирайте только параметры редактора. После импорта проверьте свойства проекта.

Если вкладка расширений сообщает `Failed to fetch`, проверьте доступ к Marketplace. Список рекомендаций остаётся в `.vscode/extensions.json`; те же расширения можно установить официальным CLI в текущий проверочный профиль:

```sh
code --profile Проверка --install-extension bmewburn.vscode-intelephense-client
code --profile Проверка --install-extension EditorConfig.EditorConfig
code --profile Проверка --install-extension xdebug.php-debug
```

После установки выполните Developer: Reload Window и снова откройте PHP-файл. Не копируйте пользовательские настройки из рабочего профиля.

Пути к PHP, JDK, браузеру и локальной БД задаются на своём компьютере. Они не должны попадать в `.vscode/`, профиль для передачи команде или общие свойства проекта.

## 4. Проверка стиля кода

Команды из корня проекта:

```sh
php ../PP03-teacher/tools/php/phpcs.phar --report=summary
php ../PP03-teacher/tools/php/phpcs.phar --report=source
php ../PP03-teacher/tools/php/phpcbf.phar
```

В PowerShell замените `/` на `\` при необходимости и укажите полный путь к `php.exe`, если PHP отсутствует в PATH. PHPCBF возвращает код 1, когда внёс исправления; итог проверяйте повторным запуском PHPCS. Код 0 у PHPCS означает отсутствие нарушений.

Проверяются PHP-файлы `src/`, `public/`, `config/`, `templates/`. В `phpcs.xml` сохранены исключения из заготовки преподавателя для смешанных HTML/PHP-шаблонов и проекта без пространств имён. Дополнительные правила ради нулевого результата не отключались.

Перед коммитом сохраните файлы, запустите PHPCS, просмотрите `git diff --check` и `git diff`. После изменения оформления проверьте запуск и контрольные сценарии. Не добавляйте исправление бизнес-логики в коммит форматирования.

## 5. Ветки и коммиты

Работайте в отдельной ветке: `practice/m04`, `fix/loan-limit`, `docs/setup`. Сообщения начинаются с назначения: `chore:`, `style:`, `refactor:`, `fix:`, `docs:`. Форматирование сохраняется отдельным коммитом `style: ...`. Сначала отправьте ветку, затем создайте Pull Request в свой `main`, перечислите изменения и фактические проверки.

При проверке передачи настроек создайте пустой профиль VS Code «Проверка», откройте новый клон, установите только рекомендации проекта и запустите его с отдельной БД. Отформатируйте 3–5 PHP-файлов командой Format Document (в Linux Ctrl+Shift+I, в Windows Shift+Alt+F), сохраните и выполните:

```sh
git status --short
git diff --exit-code
git diff --check
```

Ожидается пустой diff и ноль ошибок PHPCS. Сохраните снимок результата в материалах модуля; при расхождениях исправьте общие настройки и повторите проверку.

## 6. Чего не коммитить

Не включайте `.env`, базы данных, загруженные пользователями файлы, пароли, токены, историю редактора, каталоги расширений, исполняемые файлы PHP/JDK/IDE, кэш NetBeans и `nbproject/private/`. Не публикуйте пути к своим программам и настройки сессии. Общие файлы `.editorconfig`, `.gitattributes`, `phpcs.xml`, `.vscode/settings.json`, `.vscode/extensions.json` и `nbproject/project.properties` хранятся в Git.
